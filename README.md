# 10. 다중 사용자 자동거래 플랫폼

## 프로젝트명
다중 사용자 자동거래 및 전략 실행 플랫폼

## 수행 시기
장기 개발 및 운영 프로젝트

## 프로젝트 소개
TradingView 등 외부에서 발생한 매매 신호를 수신하여 사용자별로 설정된 거래 전략을 판단하고, 증권사 및 암호화폐 거래소 API를 통해 실제 주문까지 자동으로 실행하는 다중 사용자 자동거래 플랫폼.

사용자가 종목, 전략, 진입조건, 익절·손절 조건, 레버리지, 주문금액, 반복 실행 여부 등을 설정하면 서버가 지속적으로 전략 상태를 관리하며 매매 신호에 따라 주문을 실행하도록 개발하였다.

단순히 매매 신호를 주문 API로 전달하는 방식이 아니라,

**전략 신호 → 진입 판단 → 주문 생성 → 체결상태 확인 → 부분체결/취소/실패 처리 → 포지션 확인 → 익절·손절/청산 → 거래결과 저장**

으로 이어지는 주문 실행 흐름과 상태관리 시스템을 Backend에서 구현하였다.

Frontend, Backend, Database, 자동거래 로직 및 외부 거래 API 연동을 단독으로 개발하였다.

현재 GitHub에 보존된 소스는 Bybit/Binance 기반 암호화폐 자동거래 Backend가 중심이며, 실제 프로젝트에서는 별도로 국내 증권사 API를 이용한 국내 주식 자동거래 기능도 개발하였다.

- TradingView 전략 신호 수신

# 자동 주문 실행 엔진

## 주문 상태관리

거래소에 주문을 전송한 뒤 응답만 받고 끝내는 방식이 아니라 주문 실행 과정을 별도의 상태로 관리하였다.

주요 실행 상태:

`NEW_START → NEW_RUN → RUN → NEW_CLOSE → CLOSE`

각 상태에 따라 서버가 수행해야 할 작업을 분리하였다.

- 신규 주문 생성
- 신규 주문 체결 확인
- 포지션 실행 상태 확인
- 청산 주문 생성
- 청산 체결 확인
- 거래 종료 및 결과 저장

이를 통해 외부 거래소 주문과 내부 전략 상태를 연결하였다.

---

## 거래소 주문 상태 추적

Bybit REST API와 WebSocket을 이용하여 실제 거래소 주문 상태를 지속적으로 확인하였다.

처리하는 주요 상태:

- New
- PartiallyFilled
- Filled
- Cancelled
- Rejected
- Untriggered
- Triggered
- 기타 주문 상태

거래소의 실제 체결 결과에 따라 내부 주문 상태와 전략 상태를 갱신하였다.

---

## 부분체결 처리

주문이 한 번에 전량 체결되지 않는 상황을 고려하였다.

부분체결 및 취소 발생 시:

- 실제 체결수량 확인
- 잔여수량 계산
- 기존 주문상태 확인
- 필요 시 잔여수량 재주문
- 여러 주문 ID 저장
- 최종 체결 결과 통합

여러 개의 주문으로 나누어 체결된 경우 각 주문의 결과를 다시 조회하여 실제 체결정보를 계산하였다.

---

## 실제 체결정보 반영

거래소에서 반환되는 실제 주문 결과를 기준으로 다음 정보를 관리하였다.

- 평균 체결가격
- 누적 체결수량
- 누적 체결금액
- 거래 수수료
- 실제 포지션 수량
- 진입시간
- 청산시간

주문 요청 가격이 아니라 실제 거래소에서 체결된 데이터를 기준으로 내부 포지션 정보를 갱신하였다.

---

## 주문 재시도 및 Cooldown

거래소 주문이 취소되거나 정상적으로 완료되지 않는 경우를 처리하기 위해 주문별 Retry 및 Cooldown 상태를 관리하였다.

`order_list`에서 다음 정보를 별도로 관리하였다.

- Retry 횟수
- 현재 주문 상태
- 진입 주문 ID 목록
- 청산 주문 ID 목록
- Cooldown 시간
- 종료 유형
- Algorithm Order ID

일정 횟수 이상 주문이 정상적으로 처리되지 않는 경우 해당 주문을 종료하고 오류정보를 기록하도록 구성하였다.

---

## 거래소 WebSocket

사용자별 거래소 API 인증정보를 이용하여 Bybit Client와 WebSocket 연결을 생성하였다.

거래소의 주문 이벤트를 구독하여:

- 주문상태 변경
- 체결
- 취소
- 주문 종료

등의 이벤트를 Backend의 주문 상태와 연결하였다.

REST API를 이용한 상태 확인과 WebSocket 이벤트 처리를 함께 사용하였다.

# 실시간 사용자 상태 갱신

Socket.IO를 이용하여 Backend의 자동거래 상태변화를 사용자 화면에 전달하였다.

Socket 연결 시 JWT를 검증하고 사용자 ID와 Socket ID를 연결하였다.

이를 통해 특정 사용자의:

- 자동거래 ON/OFF
- 전략 상태 변경
- 주문 상태 변경
- 거래결과
- 서버 처리결과

등을 해당 사용자 화면에 전달할 수 있도록 구현하였다.

# 사용자별 거래소 API 연동

# 프로젝트 내 역할

다중 사용자가 각각의 매매전략과 거래계정을 설정하고 자동으로 거래를 실행할 수 있는 자동거래 플랫폼을 단독으로 개발하였다.

TradingView 등 외부 전략에서 발생하는 매매 신호를 Backend에서 수신하고 사용자별 전략 상태와 진입·익절·손절 조건을 판단하여 거래소 및 증권사 API를 통해 실제 주문을 실행하는 구조를 구현하였다.

특히 주문 요청만 전달하는 방식이 아니라 주문의 생성부터 실제 체결까지 상태를 관리하고, 부분체결·취소·재주문·주문 실패·Retry·Cooldown 및 실제 포지션을 확인하여 내부 거래상태와 외부 거래소 상태를 동기화하도록 구현하였다.

실거래와 테스트 거래 환경을 별도로 구성하고 전략, 주문, 체결결과, 수수료, 손익 및 상태변경 이력을 Database에 저장하여 거래과정을 추적하고 결과를 분석할 수 있도록 개발하였다.

또한 사용자별 거래소 API Client와 WebSocket 연결을 관리하고 Socket.IO를 통해 Backend의 거래상태 변화를 사용자 화면에 실시간으로 전달하는 다중 사용자 자동거래 시스템을 구축하였다.
